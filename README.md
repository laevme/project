# Барахолка кампуса

## О проекте

REST API для студенческой барахолки: пользователи выставляют объявления, объявления лежат в категориях, покупатели пишут продавцам сообщения и добавляют понравившиеся объявления в избранное.

Система позволяет создавать пользователей, распределять объявления по категориям, отслеживать статус объявления (активно / продано / снято), вести переписку по объявлению и сохранять избранное.

## Запуск

Нужен Docker (Docker Desktop должен быть запущен).

```bash
docker compose up -d
```

- API: http://localhost:8080
- Проверка: `curl -i localhost:8080/health` → `200 {"status":"ok"}`
- Adminer (веб-интерфейс базы): http://localhost:8081
- PostgreSQL снаружи доступен на порту `5433`
- Схема (`schema.sql`) и тестовые данные (`seed.sql`) применяются автоматически при первом запуске

Остановить: `docker compose down`.
Сбросить базу к исходному состоянию (после изменения схемы или seed): `docker compose down -v`.

### Запуск API без Docker (база в Docker)

```bash
docker compose up -d
go run .
```

## Сущности

* `users` — пользователи барахолки
* `categories` — категории объявлений
* `listings` — объявления
* `messages` — сообщения по объявлению
* `favorites` — избранные объявления

### Коды ошибок

Тело ответа об ошибке: `{"error":"описание"}`.

* `400` — некорректный `id` в пути или невалидный JSON
* `404` — запись не найдена (в том числе несуществующий `user_id`, `category_id`, `listing_id` при создании)
* `409` — конфликт: повтор `email`, повтор `slug` категории, повторная запись в избранное, попытка удалить категорию, у которой есть объявления
* `422` — не прошла валидация: пустое обязательное поле, отрицательная цена, неверный статус объявления
* `500` — внутренняя ошибка сервера (подробности только в логе)

При удалении пользователя его объявления, сообщения и записи в избранном удаляются автоматически.

Категорию с объявлениями удалить нельзя — вернётся `409`.

## Статусы объявлений

* `active` — активно, продаётся
* `sold` — продано
* `archived` — снято с публикации
